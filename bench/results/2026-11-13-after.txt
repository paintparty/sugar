sugar benchmarks before and after the Phase 3 changes, 2026-11-13.

The changes: sugar.core merges the process context once instead of on every
call, caches opts as passed (a string is parsed only on a miss), and keys the
cache on the opts alone. sugar.utils/rgb->8-bit no longer calls Math/round by
reflection. :validate-options now defaults to true.

Machine: Intel Core i5-8500B, 6 cores, macOS 15.5, load average 3 to 9.
"Before" is the committed source as of the baseline, run back to back with
"after" on the same build of the bench. Ratio is before / after, so above 1
is faster.

Rows for code the changes do not touch (empty cache, mocked context, browser
convert) show the run-to-run drift: 0.5x to 1.5x on Babashka and Node, 0.88x
to 1.26x on the JVM. Only differences outside that range mean anything.
